하위 세션에 업무를 맡긴 뒤 메인은 진행을 따라가거나 확인 호출을 반복하지 않는다. 완료 알림이 오면 그 보고를 간단히 사용자에게 전한다. 커밋·타입체크 재실행 같은 재검증은 사용자가 요청할 때만 한다.

**Why:** 사용자는 메인을 접수·조율·기록 중심으로 두고, 실행과 검증은 하위 세션에 맡기려 한다. 메인이 다시 따라가면 중복이다.

**How to apply:** 넘긴 직후에는 한 줄 안내로 끝낸다. 완료 알림이 오면 보고 내용 중 사용자가 결정할 것과 남은 것만 전한다. 알림센터처럼 분리된 작업 세션이 있는 기능은 그 세션으로 보낸다([[dentlink-fe-main-session]]).

**모든 에이전트 공통(사용자 2026-11-12):** 이 에이전트만이 아니라 모든 에이전트(사무실/집 × Codex/Claude Code, 이후 추가분)의 작업 방식이다. 메인은 특정 작업·브랜치·PR에 묶지 않고, 큰 기능은 기능 전체를 맡는 분리된 작업 세션 하나가 이어받는다. 정본은 codex `SESSION_WORKFLOW.md` "Standing feature sessions and a general main", 다른 에이전트 전달은 `AGENT_INBOX.md` 모든 에이전트 항목.

**보완(사용자 2026-11-12):** 이미 운영이 잡힌 에이전트(예: 사무실 Codex)는 똑같이 바꿀 필요 없이 기존 세션 구성을 유지하고 개념만 적용한다.

**하위 세션 보고 금지(사용자 2026-11-12):** 분리된 작업 세션은 사용자가 시키지 않으면 메인에 보고·메시지를 보내지 않는다. Claude Code는 메인이 시작한 세션의 완료 알림을 앱이 자동 전달하므로, 상시 세션이 되면 `detach_session`으로 메인에서 분리한다(알림센터 하위 세션 local_62b33d4f… 분리 완료).

**용어 구분(사용자 2026-11-12):** "하위 세션"은 메인 아래 연결돼 메인이 결과를 받아야 하는 세션(Claude `start_session` 자식, 서브에이전트)이다. 사용자가 말하는 "세션 분리"는 메인과 별개로 기능을 맡는 독립 top-level **작업 세션**이다. Claude Code에서는 `start_session`으로 만든 뒤 바로 `detach_session`으로 분리하고, 기록에서는 "작업 세션"이라 부른다.
