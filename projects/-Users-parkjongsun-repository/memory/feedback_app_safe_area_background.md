type: feedback

2026-11-17 사용자 명시 지침: 앱에 스크린을 추가할 때 반드시 적용한다. 알림 부가 크레딧/청구서 목록도 예외가 아니다. 노치/상태바·safe area·헤더·본문 배경과 inset을 기존 화면 기준으로 맞추고 진입·뒤로가기/스와이프·홈/프로필 복귀를 챙긴다. 디자인이 의도한 색 차이는 유지한다.

하단 탭과 중첩 native stack을 구분한다. 전역색을 focus/effect 시점에 바꾸는 것만으로 끝내지 않는다. 화면별 안전영역을 소유하게 했다면 각 화면/탭의 실제 색을 직접 사용하고 상위의 불완전한 하위 route 추정에 의존하지 않는다. 화면 전환 중 서로의 색을 덮거나 inset을 중복 적용하지 않는다. 루트 수정은 기존 홈/프로필의 정지 상태 배경색까지 함께 검토한다. 동등한 Office/Lab 흐름도 챙기되 Lab 프로필 흰색 등 의도된 차이는 보존한다.

Why: 여러 번 타이밍 수정 후에도 문제가 남았고, 화면별 처리로 알림은 개선됐으나 기존 탭의 노치가 흰색으로 남는 회귀가 생겼다. 탭이 자신의 색을 직접 소유하게 한 후 사용자가 해결 확인했다.
How to apply: 정본 DEVELOPMENT_STYLE.md의 App Screen Safe Areas And Background Transitions. 구현 필수 체크이며 매번 전체 테스트를 강요하는 규칙은 아니다. 실행검증은 위험 기반 및 사용자 지시를 따르고 생략 시 미검증으로 기록한다.
