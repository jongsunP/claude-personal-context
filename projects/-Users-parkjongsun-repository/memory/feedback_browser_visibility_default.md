2026-11-13 사용자 확정 지침. 에이전트 조사 중 Chrome for Testing이 반복해서 나타났다 사라지며 작업을 방해하는 상황을 피한다.

- 일반 조사·링크 열람·자동화는 적합한 연결 도구, 이용 가능한 인앱 또는 headless/비표시 실행을 우선한다. 도구가 없거나 필요한 증거를 확보할 수 없으면 그 한계를 구분한다.
- 외부 visible은 사용자가 직접 보기/실시간 작업 관찰을 요청하거나 특정 검증에 실제로 필요할 때 사용한다. CfT 우선은 브라우저 격리 선택이지 외부 창 표시 의무가 아니다.
- 적합한 agent-owned 브라우저/context/tab을 재사용하고 단계마다 새로 실행·종료하거나 포커스를 가져오지 않는다. 타 세션/사용자 창은 종료하지 않는다.
- visible:false 탭과 실제 OS 창/앱 활성화는 다를 수 있다. 깜박임이 남는 경로를 반복하지 말고 지원되는 덜 방해되는 방식으로 전환하거나 한계를 알린다.
- 직접 user preview의 표시 창 검증, 앱 최종 코드 런타임 검증, 명시적인 headed E2E 요청은 유지한다.
- 정본은 codex-personal-context의 SESSION_WORKFLOW.md “Web Browser Automation Preference”. AGENTS.md와 AI_WORKFLOW.md에도 반영했다.
- 사용자 정정: 대상 두 세션은 통합알림센터 `01a065e6-afb2-75a0-b465-61c3e488a894`와 해외 API 조사 `01a1d352-b346-7872-b537-6fe5ffaf4f87`다. 통합알림센터 추가 전달 완료, 기존 마케팅 동의 전달은 사용자 지시대로 유지한다. 진행 상태와 범위는 유지하고 표시 방식만 적용하며 메인은 폴링하지 않는다. 최초 기록 조사는 마케팅 동의/해외 API 대상이었으므로 통합알림센터 실행 원인을 검증했다고 하지 않는다.
