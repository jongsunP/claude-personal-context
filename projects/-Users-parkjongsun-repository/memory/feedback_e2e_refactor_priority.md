E2E 리팩토링 검토 순서는 아래 우선순위를 따른다.

**Why:** E2E 테스트는 실제 사용자 흐름을 재현하는 것이 목적이므로, 동작 정확성이 가장 중요하다. 코드 미학은 마지막.

## 우선순위

1. **테스트 정확성** (최우선)
   - 테스트가 의도한 시나리오를 제대로 검증하는가
   - 잘못된 셀렉터, 잘못된 버튼 타겟팅, 조건 코드가 필수 액션을 가리고 있지 않은가
   - 플레이크(flaky) 원인 제거

2. **테스트 실행 시간 단축**
   - 불필요한 sleep, networkidle 남용, 브라우저 기반 처리를 API 호출로 교체
   - global-setup/teardown의 속도 개선 포함

3. **재사용성**
   - 다른 시나리오에서도 쓸 수 있는 step 함수인가
   - spec에 인라인된 로직 중 steps/utils로 분리할 만한 것
   - 새 spec 작성 시 기존 함수 조합만으로 충분한 구조인가

4. **가독성 / 코드량** (마지막)
   - 주석 정리, 변수명 개선, 중복 코드 제거
   - 실제 애플리케이션 코드 수준의 품질 기준은 E2E에서는 후순위

**How to apply:** E2E 리팩토링 요청이 오면 이 순서로 검토 항목을 정리한 뒤 보고한다. 가독성 이슈가 있더라도 정확성·시간·재사용성 문제가 없으면 별도 언급 없이 넘어간다.
