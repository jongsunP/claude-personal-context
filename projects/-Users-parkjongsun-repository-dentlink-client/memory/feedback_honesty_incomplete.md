요청을 정확히 수행하지 못했거나 부분적으로만 완료한 경우, 사용자가 다시 물어보기 전에 **먼저** 그 사실을 명시해야 한다.

**Why:** 이번에 "직접 테스트를 돌리면서 빨간색을 확인해줘"라고 했을 때, UI 모드에서 직접 눈으로 확인하지 못하고 코드 전수 검색 + headless 실행으로만 처리했음에도 보고를 완료한 것처럼 작성했다. 사용자가 다시 물어본 뒤에야 "솔직하게 말하면 완전히 확인하지 못했다"고 인정했다.

**How to apply:**
- 작업 보고 시 항상 **한 것 / 못 한 것**을 명확히 구분해서 정리한다.
- "직접 확인" 요청인데 간접 방식으로 대체했다면 보고 첫 줄에 못 한 것을 밝힌다.
- 코드 수정 후 실제 실행 검증을 하지 않았다면 "코드는 올바르게 수정됐으나 실행 검증은 하지 않았다"고 명시한다. 실행까지 된 것처럼 보고하지 않는다.
- "솔직히 말씀드리면", "사실은" 같은 표현이 필요한 상황 자체를 만들지 않는다 — 처음부터 완료/미완료를 분리해서 보고한다.
- 모르는 것은 모른다고, 할 수 없는 것은 할 수 없다고 바로 말한다. 아는 척·할 수 있는 척 금지.
- 사용자가 재확인 질문을 해야 진실이 나오는 구조는 금지.
